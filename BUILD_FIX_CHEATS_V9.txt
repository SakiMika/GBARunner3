GBARunner3 cheat v9 runtime fix

Root cause addressed
====================
CheatService.o was moved to .ewram at 0x0204xxxx to save VRAM A space. The
ARM9 MPU marks main memory as data-cached before crt0 copies .ewram. crt0 copied
the .ewram image with normal stores but never cleaned those dirty D-cache lines.
That was fine while .ewram contained only data, because later data loads see the
D-cache. It is NOT safe for executable code: ARM instruction fetch does not read
dirty D-cache lines. Calling CheatService code can therefore fetch stale RAM and
hang while the bootstrap splash is still visible.

v9 changes
==========
1. crt0 cleans+invalidates the copied .ewram D-cache lines, drains the write
   buffer, and invalidates I-cache before __libc_init_array / gbaRunnerMain.
2. CheatService is made trivially BSS-initialized so there is no early global
   constructor in .init_array. LoadForRom explicitly resets its state.
3. The disabled VBlank cheat-hook test no longer clobbers r12, which is a live
   guest register. lr is used as scratch instead, matching the stock VBlank path.
4. All v8 fixes remain: EWRAM BSS placement, ARM7 touchReadXY, dedicated cheat
   IRQ stack, multi-line cheat parser and V49E00/V49E01 lookup.

Expected test
=============
- Runner must leave the bootstrap splash and start Drill Dozer.
- Bottom screen shows [CHEAT] when the ROM cheat JSON is present.
- Tap [CHEAT] to pause/open list; D-pad navigates; A toggles; tap again resumes.
