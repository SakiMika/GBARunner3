GBARunner3 cheat support - v5 linker/BSS fix

Observed build failure:
  ld: address 0x068202b4 of arm9.elf section `.bss' is not within region `vrama'

VRAM A is 0x06800000..0x0681ffff (128 KiB), so the failing image exceeded
VRAM-A BSS by 0x2B4 = 692 bytes.

v5 changes:
1. Force every .bss/.bss.* / GNU linkonce BSS symbol emitted by CheatService.o
   into .ewram.bss. This also catches compiler-generated auxiliary state.
2. Remove CheatService.o from the normal VRAM-A .bss wildcard.
3. Remove strstr/strchr/strcpy/strcmp usage from the cheat JSON parser and use
   small local routines instead, preventing cheat parsing from pulling extra
   libc objects/state solely for those helpers.
4. Move SdCache's 512-entry FAT cluster table (2048 bytes) from VRAM-A BSS to
   EWRAM. This table is storage metadata, not JIT/IRQ/palette hot state. The
   move alone recovers 2 KiB, comfortably more than the observed 692-byte
   overflow.
5. Build error summary now includes ld "not within region" diagnostics.
6. GitHub Actions uploads arm9.map when available for exact section/symbol
   diagnosis if another linker issue occurs.

Cheat behavior and Drill Dozer V49E00/V49E01 test files are unchanged.
