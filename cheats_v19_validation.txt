GBARunner3 cheats v19 validation
================================

Goal 1: fix lower LCD corruption
- v18 used VRAM C for the closed [CHEAT] direct-display strip.
- VRAM C/D are also GBARunner3's center-and-mask capture ping-pong buffers.
- v19 moves the closed strip to VRAM B (physical LCDC address 0x06820000).
- HBlank no longer disables REG_DISPCAPCNT and no longer remaps VRAM C.
- At VCOUNT 175 only:
    VRAMCNT_B = 0x80 (LCDC)
    REG_DISPCNT = 0x00060000 (direct display VRAM B)
    main master brightness = normal
- At VBlank before the stock capture swap:
    VRAMCNT_B = 0x91 (MAIN_BG + 0x40000)
    REG_DISPCNT = latest gCheatPendingDispCnt
    main master brightness = black
- r0-r12 guest register preservation is maintained: the overlay path uses only lr/r13.

Goal 2: multi-line cheat test
Both cheats/V49E00.json and cheats/V49E01.json now include:

Multi Jump
D0000020 0001
33000E3C 0004
D0000020 0001
83000EA6 FFFC

Executor path:
- D0000020 0001 -> type D button conditional; gates exactly the next line.
- 33000E3C 0004 -> type 3, 8-bit write 0x04 to 0x03000E3C.
- D0000020 0001 -> second button conditional.
- 83000EA6 FFFC -> type 8, 16-bit write 0xFFFC to 0x03000EA6.
- MaxCodeLines is 24, so the four lines remain a single cheat entry.

Static checks performed
- Both JSON files parse successfully.
- Both Multi Jump entries contain exactly 4 code lines.
- HBlank overlay contains no VRAM C remap and no capture-stop write.
- VBlank restore does not use r12 before the guest-register-preserving C tail.

Build limitation
- devkitPro/devkitARM is not installed in this execution environment, so the final ARM9 link and hardware behavior were not executed here.
